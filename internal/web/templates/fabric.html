VXVisor Fabric

{{if .V.Admin}}{{end}}

A fabric stretches port groups across hosts. A VM on a fabric port group reaches the others on it at layer 2 wherever they run, and keeps its address when it moves. Routed port groups get a distributed gateway: the same gateway address answers on every host, so traffic between port groups is routed on the host where the VM runs. Hosts reach each other over a dedicated underlay (a NIC, or a VLAN on a non-management uplink). The control plane is BGP EVPN, the data plane VXLAN. Traffic between two port groups is denied until a row in the connectivity table allows it. Inside one port group, traffic is always allowed.

Deploy fabric

  1. Hosts
  2. Underlay
  3. Access
  4. Check & deploy

Name the fabric and pick its hosts. Port groups you create on it can then exist on every one of them.

Hosts {{range .V.Nodes}}{{end}}

How each host reaches the others: a free NIC (untagged), or a VLAN on a NIC that has no other role. Management is never offered, and a VLAN's parent is never changed. Every TEP must be in one subnet that nothing else on the hosts uses.

Which organizations' admins may build port groups and rules on this fabric? Instance admins always can. Each organization gets its own routing domain.

{{range .Orgs}}{{end}}

Every host is checked before anything changes. On deploy each host sets up its underlay, VRFs and BGP EVPN. Then every pair of hosts must reach each other at full MTU with DF set. If anything fails, the fabric is removed again.
