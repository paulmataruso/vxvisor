Build your network from the bottom up — Physical adapter (one network port, or several joined into a NIC team) → vSwitch → Port Group (a VLAN) → VMs. A NIC team can balance traffic with no switch setup, use LACP or a static EtherChannel, or act as active/standby failover. Build your network from the bottom up — External network (provisioned by your provider) → vSwitch → Port Group (a VLAN) → VMs. Every vSwitch belongs to this organization alone. Connect one to an external network to carry it out to the physical network: an access external network carries one port group (the native one), a QinQ or dedicated one carries them all, each on its own VLAN. To route instead, leave a port group's gateway blank and attach it to a gateway (vRouter) on the vRouters page.

A Port Group is a VLAN on a vSwitch that VMs connect to. With a gateway it's standalone: its own gateway and DHCP, reachable only by its own VMs. Leave the gateway blank to route it with a gateway (vRouter), or to carry it out the external network (the upstream network routes it). The native port group is the one the external network carries untagged. A port group's subnet and gateway can be edited only while nothing is attached to it.

Add NIC teaming to

Teams the current physical adapter with the ports you pick below and moves this vSwitch onto the team, in one step. On the management vSwitch it's applied with an automatic rollback, so the admin connection can never be lost.

Edit NIC team

MTU for

1500 is standard Ethernet; 9000 is the usual jumbo-frame size. It is set on the vSwitch, its physical adapter (every NIC of a team) and the VMs' ports on it. The physical switch ports must allow the same size, and each VM must set the MTU on its own NIC to send jumbo frames.

{{end}}
